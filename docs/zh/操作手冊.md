# OpenReply 手動操作手冊（只有你本人能做的步驟）

這份手冊列出部署 OpenReply 時，**必須由你本人登入帳號操作**的步驟。其他安裝、部署、設定程式的工作由總指揮處理。

本次部署方案（v2，全部放在 Railway）：

| 元件 | 放在哪裡 |
| --- | --- |
| 網站（Next.js，web 服務） | Railway |
| Worker（寄 DM 的背景程式，worker 服務） | Railway |
| PostgreSQL 資料庫、Redis | Railway |
| 登入信（magic link） | Gmail SMTP ＋ 應用程式密碼 |
| Instagram 連線 | 自建 Meta App，只給你自己的帳號用（不需要 App Review） |

## 開始前請先讀：機密資訊的規則

- **可以交給總指揮的**：網域、IG 帳號名稱、Gmail 地址、GitHub 帳號名稱、fork 的 repo 網址等「別人看到也無妨」的資訊。
- **不可以貼到聊天的**：密碼、應用程式密碼、資料庫連線字串、App Secret、`ENCRYPTION_KEY` 等各種金鑰。
  這些一律 **請自己貼到平台（Railway 的 Variables 頁、Meta 後台），不要貼到聊天**。
- 如果不小心把機密貼到聊天或任何可能被記錄的地方，請立刻到該平台重新產生（rotate）一組新的。

文中的 `https://<你的-railway-網域>` 是佔位符，格式像 `https://openreply-production-xxxx.up.railway.app`。等 Railway 的 web 服務產生網域、總指揮告訴你實際網域後，再把它替換進去。

## 第一部分：現在就可以同步進行

以下 1–4 項彼此不相依，可以同時開始，不用等總指揮。

### 1. 註冊 Meta 開發者帳號

Meta 開發者帳號的驗證有時要等，所以最先做。

- [ ] 用你的 Facebook 帳號登入 <https://developers.facebook.com>。
- [ ] 點右上角「開始使用」（Get Started）註冊成開發者。
- [ ] 依畫面完成驗證，**可能需要手機簡訊驗證**（也可能要求驗證 email）。
- [ ] 同意開發者條款，職業類別隨意選（例如「開發人員」或「創作者」）。
- [ ] 完成後能進入 <https://developers.facebook.com/apps>，看到「建立應用程式」按鈕即可。App 本身等第三部分再建立。

**完成後要交給總指揮的資訊：** 「Meta 開發者帳號已開通」的確認。

### 2. Fork OpenReply 到你的 GitHub

- [ ] 登入 GitHub，打開 <https://github.com/diwenne/openreply>。
- [ ] 點右上角「Fork」→ Owner 選你自己的帳號 → Repository name 保持 `openreply` → 按「Create fork」。
- [ ] 確認網址變成 `https://github.com/<你的帳號>/openreply`。

**完成後要交給總指揮的資訊：** fork 的 repo 網址（例如 `https://github.com/your-name/openreply`）。

### 3. 把 Instagram 切換成專業帳號（創作者或商業）

OpenReply 只能連接 **專業帳號**，一般個人帳號無法連線。

#### 創作者 vs 商業帳號，差在哪？

| | 創作者帳號（Creator） | 商業帳號（Business） |
| --- | --- | --- |
| 適合對象 | 個人品牌、網紅、內容創作者 | 店家、品牌、公司 |
| 個人檔案顯示 | 可選擇類別（例如「數位創作者」） | 可顯示聯絡方式、地址、營業類別 |
| 收件匣 | 主要／一般 兩個分頁 | 單一收件匣 |
| 音樂素材 | 可用完整音樂庫 | 部分商業帳號音樂受限 |
| 是否需要連結 Facebook 粉專 | 不需要 | 不需要（本專案用 Instagram Login） |
| OpenReply 能不能用 | ✅ 可以 | ✅ 可以 |

**建議：** 如果你是個人經營內容，選 **創作者帳號**（保留完整音樂庫、較貼近個人帳號的使用體驗）。如果是店家或品牌，選 **商業帳號**。兩者對 OpenReply 的功能沒有差別，之後也可以互相切換。

#### 操作清單

- [ ] 在手機打開 Instagram，進入你的個人檔案。
- [ ] 點右上角選單（三條線）→「設定和動態」。
- [ ] 找到「帳號類型和工具」（舊版可能叫「帳號」）→「切換為專業帳號」。
- [ ] 選擇類別，接著選「創作者」或「商業」。
- [ ] 確認帳號**不是私人帳號**（專業帳號必須公開）。
- [ ] 完成後回到個人檔案，確認上方出現「專業主控板」。

**完成後要交給總指揮的資訊：** IG 帳號名稱（例如 `@your_account`），以及選了「創作者」還是「商業」。

### 4. Gmail：開啟兩步驟驗證並產生應用程式密碼

OpenReply 登入只靠 email 登入連結（magic link），所以一定要能寄信。我們用 Gmail 的 SMTP 寄信，這需要「應用程式密碼」，而應用程式密碼必須先開啟兩步驟驗證才能產生。

- [ ] 用電腦登入要拿來寄信的 Gmail 帳號，打開 <https://myaccount.google.com/security>。
- [ ] 在「你登入 Google 的方式」找到「兩步驟驗證」，依畫面開啟（通常用手機簡訊或 Google 提示）。
- [ ] 開啟後，打開 <https://myaccount.google.com/apppasswords>。
  （如果找不到這頁，代表兩步驟驗證還沒真的開好；公司或學校管理的帳號也可能被管理員關閉此功能，請改用個人 Gmail。）
- [ ] 應用程式名稱輸入 `OpenReply`，按「建立」。
- [ ] 畫面會顯示一組 16 個英文字母的密碼，例如 `abcd efgh ijkl mnop`。**這組只會顯示一次**，請先存到密碼管理器。
- [ ] 之後貼到平台時 **把中間的空格全部拿掉**，變成 `abcdefghijklmnop`。

這組密碼要等 Railway 的 web 服務建好後才貼進去，做法在第二部分的第 7 項。

**完成後要交給總指揮的資訊：** 寄信用的 Gmail 地址、允許登入的 email 清單。⚠️ 應用程式密碼：**請自己存好，不要貼到聊天**。

## 第二部分：Railway

### 5. 授權 Railway 讀取 GitHub fork

Railway 要能讀到你的 fork，才能部署 web 和 worker 服務。只授權這一個 repo，不要給整個 GitHub 帳號的權限。

- [ ] 用 GitHub 帳號登入 <https://railway.com>（第一次使用會建立 Railway 帳號）。
- [ ] 在 Railway dashboard 點「New Project」→「Deploy from GitHub repo」，或到 Account Settings → Integrations 找到 GitHub。
- [ ] 點「Configure GitHub App」，會跳到 GitHub 的安裝頁面。
- [ ] 選你自己的 GitHub 帳號。
- [ ] Repository access 選 **「Only select repositories」**，只勾 **`openreply`**（你在第 2 項 fork 的那個）。
  ❌ 不要選「All repositories」。
- [ ] 按「Install」（或「Save」）回到 Railway，確認清單裡看得到 `<你的帳號>/openreply`。

**完成後要交給總指揮的資訊：** 「Railway 已能看到 openreply repo」的確認。之後建立服務、設定建置指令由總指揮處理。

### 6. Railway 用量上限

Railway 依用量計費。設好上限可以避免程式出錯時產生意外帳單。

- [ ] 在 Railway dashboard 左上角切到你的 Workspace → **Workspace Settings** → **Usage**。
- [ ] 找到用量上限（Usage Limits），設定 **硬上限（Hard limit）15 美元**。
  > 注意：達到硬上限時，Railway 會停掉這個 Workspace 的服務（網站和 worker 都會停），不會繼續扣款。
- [ ] 同一頁開啟 **用量提醒**（Custom email alert），建議設在 10 美元左右，快到上限前先收到 email 通知。
- [ ] 儲存。

**完成後要交給總指揮的資訊：** 硬上限金額、用量提醒金額。

### 7. 在 Railway web 服務填入 Gmail 與登入限制

等總指揮通知「web 服務已建立」後再做。

`EMAIL_SERVER` 的格式如下（使用 465 埠、`smtps://` 隱含 TLS）：

```
smtps://你的帳號%40gmail.com:應用程式密碼@smtp.gmail.com:465
```

**URL 編碼規則：** 帳號裡的 `@` 必須寫成 `%40`，否則系統會把它誤認為分隔符號。例如：

| 原始值 | 貼進 `EMAIL_SERVER` 時寫成 |
| --- | --- |
| 帳號 `amy.chen@gmail.com` | `amy.chen%40gmail.com` |
| 應用程式密碼 `abcd efgh ijkl mnop` | `abcdefghijklmnop`（去掉空格；Gmail 應用程式密碼只有小寫字母，不需要其他編碼） |

組合起來的樣子（僅示意，請換成你自己的）：

```
smtps://amy.chen%40gmail.com:abcdefghijklmnop@smtp.gmail.com:465
```

到 Railway → 你的專案 → **web 服務** → Variables，新增以下三個：

| 變數 | 值 |
| --- | --- |
| `EMAIL_SERVER` | 上面組好的字串 |
| `EMAIL_FROM` | `OpenReply <你的帳號@gmail.com>`（寄件人必須是同一個 Gmail 地址，否則 Gmail 會改寫或拒寄） |
| `ALLOWED_EMAILS` | 你自己要用來登入的 email，多個用逗號分隔。沒設的話，任何人打開你的網址都能註冊一個工作區 |

- [ ] 在 **web 服務** 新增 `EMAIL_SERVER`。
- [ ] 在 **web 服務** 新增 `EMAIL_FROM`。
- [ ] 在 **web 服務** 新增 `ALLOWED_EMAILS`。
- [ ] **worker 服務不要設這三個**：登入信只由 web 服務寄出，worker 不寄信；機密少放一處比較安全。
- [ ] 按畫面上方的「Deploy」（或「Apply changes」）讓變數生效。

> 用 `EMAIL_SERVER` 之後就 **不需要** `RESEND_API_KEY`。

**完成後要交給總指揮的資訊：** 「web 服務已設好 `EMAIL_SERVER`、`EMAIL_FROM`、`ALLOWED_EMAILS`」的確認。⚠️ 應用程式密碼：**請自己貼到平台，不要貼到聊天**。

### 8. 貼上已產生好的金鑰

總指揮已把以下值產生好，放在專案根目錄的 **`.env.production.local`**。請打開這個檔案，**自己複製貼到 Railway 和 Meta 的 webhook 驗證欄位**（這些值不走聊天，總指揮不會在聊天裡告訴你）：

| 變數 | 貼到哪裡 |
| --- | --- |
| `NEXTAUTH_SECRET` | Railway web 服務、worker 服務 |
| `CRON_SECRET` | Railway web 服務 |
| `ENCRYPTION_KEY` | Railway web 服務、worker 服務（兩邊**必須完全相同**，否則 worker 解不開 IG 權杖、所有私訊都會失敗） |
| `WEBHOOK_VERIFY_TOKEN` | Railway web 服務，以及第 13 項的 Meta webhook「驗證權杖」欄位 |
| `META_GRAPH_API_VERSION` | Railway web 服務、worker 服務 |

- [ ] 逐一貼到上表對應的服務。
- [ ] 貼完按「Deploy」讓變數生效。

### 9. 備份 ENCRYPTION_KEY 到密碼管理器

`ENCRYPTION_KEY` 用來加密存在資料庫裡的 Instagram 權杖。**它一旦遺失或被改掉，所有已連接的 IG 帳號都要重新連線**，而且無法從資料庫還原。

- [ ] 打開 `.env.production.local`，複製 `ENCRYPTION_KEY` 的值（64 個十六進位字元）。
- [ ] 在你的密碼管理器（例如 1Password、Bitwarden、iCloud 鑰匙圈）新增一筆，名稱例如「OpenReply ENCRYPTION_KEY」，把值貼進去。
- [ ] 核對一次：密碼管理器裡的值、Railway web 服務的值、worker 服務的值，三者完全一樣。
- [ ] 建議也把 `.env.production.local` 裡其他值一起存進同一筆，方便日後重建。
- [ ] **不要**把這個值貼到聊天、email、雲端筆記或任何 git repo。

**完成後要交給總指揮的資訊：** 「ENCRYPTION_KEY 已備份」的確認（不要附上值）。

## 第三部分：建立 Meta App（對應 setup.md 的 Step 4–9）

這是最花時間的部分。請先等 Railway web 服務部署完成、拿到 `https://<你的-railway-網域>` 再開始第 12 項之後的步驟。

> ⭐ 最常被漏掉、導致「全部設好卻什麼都沒發生」的步驟：
> 1. **測試者邀請一定要在 Instagram App 裡按「接受」**（第 11 項）。只在 Meta 後台送出邀請是不夠的。
> 2. **Webhook 的 `comments` 和 `messages` 兩個欄位都要訂閱**（第 13 項）。
> 3. **App 一定要發布成 Live**（第 14 項）。在開發模式（Development）下，真實留言的 webhook 不會送過來。

### 10. 建立 Meta App 並取得三個機密值（Step 4–5）

- [ ] 打開 <https://developers.facebook.com/apps>（第 1 項已註冊好開發者帳號）。
- [ ] 點「建立應用程式」（Create App）。
- [ ] 應用程式類型選 **Business（商家）**。
- [ ] 聯絡 email 填一個你真的會看的信箱。
- [ ] 要求新增使用案例（use case）時，把篩選切到「全部」，選 **「管理 Instagram 上的訊息和內容」（Manage messaging and content on Instagram）**。
  - ❌ 不要選「使用 Marketing API 建立和管理廣告」
  - ❌ 不要選「使用 Facebook 登入進行驗證」（選錯會讓之後的登入出現 client 不符的錯誤）
- [ ] 如果不小心加了 Marketing API 使用案例，請移除它，否則會卡住發布。

接著取得三個機密值：

| 環境變數 | 在哪裡找 |
| --- | --- |
| `INSTAGRAM_APP_ID` | Instagram 產品 → 「使用 Instagram 登入的 API 設定」，一串數字（例如 `2036...`） |
| `INSTAGRAM_APP_SECRET` | 同一頁，按「顯示」 |
| `FACEBOOK_APP_SECRET` | 應用程式設定 → 基本資料 → 應用程式密鑰，按「顯示」 |

- [ ] 注意：**`INSTAGRAM_APP_ID` 不是「基本資料」頁上那個 Facebook 應用程式編號**，要用 Instagram 產品底下那一個。
- [ ] 兩個 Secret 都要設（程式會用兩個都驗證 webhook 簽章）。
- [ ] 把這三個值貼到 Railway 的 **web 服務** 和 **worker 服務**（兩邊都要，值相同），然後按「Deploy」。

### 11. 把你的 IG 帳號加為測試者，並在 IG 裡按接受（Step 6）

這一步漏掉會在 Instagram 登入畫面看到「Insufficient Developer Role」錯誤。開發階段只有對 App 有角色的帳號能連線，**連你自己的帳號也要加**。分成兩半，**兩半都必須完成**。

**前半：在 Meta 後台送出邀請**

- [ ] App 後台左側 →「應用程式角色」→「角色」（新版後台也可以從 Instagram 產品的「產生存取權杖」進去）。
- [ ] 找到「Instagram 測試人員」區塊，點新增。
- [ ] 輸入第 3 項那個 IG 帳號的**完整帳號名稱**（拼字要完全一樣），送出邀請。

**後半：在 Instagram 裡按「接受」← 最常被漏掉！**

- [ ] 用手機打開 Instagram，登入**同一個**帳號。
- [ ] 個人檔案 → 右上角選單 →「設定和動態」。
- [ ] 進入「應用程式和網站」（舊版：網站權限 → 應用程式和網站）。
- [ ] 打開「測試人員邀請」（Tester invites）。
- [ ] 找到你的 App，按 **「接受」**。
- [ ] 如果看不到邀請：確認帳號名稱拼字正確、帳號已是專業帳號（第 3 項），然後重新送一次邀請。

### 12. 登記 OAuth 重新導向網址（Step 7）

- [ ] Instagram 產品 →「設定 Instagram 商家登入」→「商家登入設定」。
- [ ] 在「OAuth 重新導向 URI」欄位加入（**結尾不要加斜線**）：

```
https://<你的-railway-網域>/api/instagram/callback
```

- [ ] 儲存。
- [ ] 畫面上的「內嵌網址（Embed URL）」**不用理它**，OpenReply 會自己產生登入網址。

### 13. 設定 Webhook（Step 8）

- [ ] 在 Instagram 產品裡找到「設定 Webhooks」。
- [ ] 回呼網址（Callback URL）：

```
https://<你的-railway-網域>/api/webhook
```

- [ ] 驗證權杖（Verify token）：打開 `.env.production.local`，自己複製 `WEBHOOK_VERIFY_TOKEN` 的值貼上（必須和 Railway web 服務上設的完全一樣）。
- [ ] 按「驗證並儲存」，應該馬上成功。如果按鈕是灰的，點進 verify token 欄位重新貼一次（改過網址常會把它清掉）。
- [ ] **訂閱欄位：`comments` 和 `messages` 兩個都要訂閱，缺一不可。**
  - [ ] `comments` 已訂閱：留言觸發私訊，最主要的功能。
  - [ ] `messages` 已訂閱：私訊與限時動態回覆觸發。
  - ⚠️ 只訂閱 `comments` 的話，活動裡「私訊也觸發」的開關會看起來有開，但**永遠不會動作**，而且不會有任何錯誤訊息。請再回頭確認一次兩個都是「已訂閱」。
- [ ] （可選）測試：點 `comments` 旁的「測試」，再點「傳送到我的伺服器」。要按**第二個按鈕**才會真的送出。完成後告訴總指揮，由總指揮確認資料庫有沒有收到。

### 14. 發布 App 成 Live（Step 9）← 必做！

**只有 Live 狀態的 App，真實留言的 webhook 才會送過來。** 開發模式下只有後台的「測試」按鈕會送事件。這是「全部設好卻什麼都沒發生」最常見的原因。

- [ ] 左側選單點「發布」（Publish）。
- [ ] 先填好三個網址（OpenReply 已內建這些頁面），否則不能發布：

| 欄位 | 網址 |
| --- | --- |
| 隱私權政策網址 | `https://<你的-railway-網域>/privacy` |
| 服務條款網址 | `https://<你的-railway-網域>/terms` |
| 資料刪除網址 | `https://<你的-railway-網域>/data-deletion` |

- [ ] 按發布，確認 App 頂端狀態從「開發中（Development）」變成 **「上線（Live）」**。
- [ ] 如果 Meta 要求先做 App Review 才能發布，先停下來告訴總指揮（只給自己用的帳號通常不需要）。

> 提醒：發布成 Live **不等於**任何人都能連。你的 App 仍然只有「標準存取權限」，只適用於對 App 有角色的帳號。以後要連第二個 IG 帳號，要對那個帳號重做一次第 11 項（邀請 ＋ 在 IG 裡接受）。

### 15. 在 OpenReply 連接 Instagram

- [ ] 打開 `https://<你的-railway-網域>`，用 email 登入連結登入（信會從第 4 項的 Gmail 寄出）。
- [ ] 進入 Settings → 點「Connect Instagram」，在 Instagram 授權畫面按同意。
- [ ] 確認帳號出現在 OpenReply 裡。

### 第三部分完成後要交給總指揮的資訊

- Meta App 名稱
- `INSTAGRAM_APP_ID`（這是公開的應用程式編號，可以給；如果不確定，也可以只說「已貼好」）

## 常見錯誤對照

| 看到的狀況 | 通常原因 | 回到哪一項 |
| --- | --- | --- |
| IG 登入畫面顯示 `Insufficient Developer Role` | 沒加測試者，或加了但沒在 IG 裡按接受 | 11 |
| 連線時出現 `redirect_uri mismatch` | OAuth 重新導向網址少登記、打錯或多了結尾斜線 | 12 |
| 後台測試按鈕有效，但真實留言沒反應 | App 還在開發模式 | 14 |
| 留言有觸發，但「私訊觸發」從來不動作 | webhook 沒訂閱 `messages` | 13 |
| 收不到登入信 | `EMAIL_SERVER` 格式錯（`@` 沒寫成 `%40`、密碼有空格）、設在 worker 而不是 web 服務，或改完沒按 Deploy | 7 |
| 私訊全部失敗、日誌出現解密錯誤 | web 和 worker 的 `ENCRYPTION_KEY` 不一樣 | 8、9 |
| 網站和 worker 突然全部停掉 | 達到 Railway 用量硬上限 | 6 |
