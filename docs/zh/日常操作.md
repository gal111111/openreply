# OpenReply 日常操作（給新同事）

這份只講公司日常怎樣用，不講部署和 Meta 審核（那些在同一資料夾的《操作手冊》和《Meta審核準備》）。

**一句話：有人在我們的片下留言、或者私信我們關鍵字，OpenReply 就自動私信對方資料，並在留言下面公開回覆。**
平常新片發佈後，系統會自動建好活動，大部分時候你不用手動設定。

## 1. 登入（先看這個）

- 網址：<https://openreply.up.railway.app>
- 登入方式：電郵登入連結（magic link），不用密碼。
  1. 在登入頁輸入登入電郵：`gagagali2004@gmail.com`
  2. 到這個 Gmail 收信，點信裡的登入連結。
- 連結只能用一次，而且要在**同一個瀏覽器**打開。打不開或者顯示過期，就回登入頁重新要一封。
- 誰管理：這個登入信箱由公司負責人持有（用戶）；系統維護和改設定由 OpenReply 的負責 session 處理。
- 想加新同事登入：要由管理員在 Railway 的 `openreply-web` 服務，把同事電郵加進 `ALLOWED_EMAILS`（逗號分隔），再重新部署。沒有加進去的電郵，收不到登入連結。

## 2. 怎樣加關鍵字

關鍵字的意思是：觀眾**私信**我們這個詞，就收到對應資料。

**方法一（建議，不用手動）**：在片的 caption 結尾寫
`Follow @skillaihk 再 DM「關鍵字」，我哋一步一步教你`
片發佈後，發片流程會自動建好活動，並把關鍵字加進私信選單。

**方法二（沒有自動建好時補跑）**：在出片專案（ig）執行

```bash
python3 tools/openreply_sync.py post/<片的資料夾> --dry-run   # 先預覽
python3 tools/openreply_sync.py post/<片的資料夾>             # 正式建立或更新
```

**方法三（手動在網頁）**：側邊「自動回覆活動」→「新增活動」，選帳號和貼文，填關鍵字。中文關鍵字要選「部分比對」，否則「我要主頁」這類句子配不中。

**規則**
- 不分大小寫；一個活動最多 10 個關鍵字。
- **同一個關鍵字不要開兩個啟用中的活動。** 否則同一個人會收到兩則私信。加之前先看現有關鍵字：`python3 tools/openreply_sync.py --menu --dry-run`。
- 關鍵字要簡短，容易打，不要用常見詞（例如「你好」）。

## 3. 怎樣改私信文案

- 一則私信最多 **1000 個字**。超過的資料要拆成幾個活動，各用同一個關鍵字（例子：`ops/openreply_s8_newspaper.py`）。
- 改某條片的私信：改該片資料夾的 `openreply_dm.txt`（只放資料本身，**不要**寫「多謝你…」，系統會自動加開頭和結尾），再跑方法二的指令。已建的活動會更新，不會重複。
- 沒有 `openreply_dm.txt` 時，私信內容取自 caption。
- 公開回覆（留言下面那句）：改 `tools/openreply_sync.py` 的 `GENERIC_REPLIES`；其他帳號在 `REPLIES_BY_KEY`。每個活動最多 10 句，系統隨機輪流用。
- **私信文字本身每次都一樣**，不能輪替；想要變化，只有公開回覆做得到。
- 在網頁直接改文案也可以，但下次跑同步指令時，會被檔案內容覆蓋。所以以檔案為準。

## 4. 怎樣看結果

| 想知道 | 去哪裡看 |
|---|---|
| 帳號有沒有連好 | 「帳號總覽」：帳號旁邊要寫「Webhook 已就緒」 |
| 每個活動傳了幾則 | 「自動回覆活動」列表 |
| 逐條私信有沒有送達 | 「私訊紀錄」：看「已傳送」或「失敗」和原因 |
| 整體有沒有問題 | 「系統診斷」 |

最直接的核對方法：用另一個帳號在片下留言，或私信關鍵字，看有沒有收到私信。

## 5. 不要做的事（2026-10-04 發生過重複私信事故）

- 不要為同一個關鍵字開兩個啟用中的活動。
- 同一個 IG 帳號，不要同時在 SEO 系統開自動回覆規則。要改由 SEO 回覆，先把 OpenReply 的活動全部停用。
- 暫停活動要定好重開的時間，否則在暫停期間來的客人收不到資料。
- 只回覆主動留言或私信我們的人，不主動發訊息、不追蹤別人、不刷讚。
- 情感帳號的自動回覆必須附求助熱線，並寫明「呢度唔提供輔導」；財經帳號必須寫「唔係投資建議」。

## 6. 出了問題先查

| 情況 | 先查 |
|---|---|
| 沒有回覆 | 活動是否「啟用中」；帳號是否「Webhook 已就緒」；關鍵字是否打對 |
| 留言有公開回覆但沒有私信 | 「私訊紀錄」看失敗原因。Meta 規定每則留言只能私信一次，而且要在 7 天內 |
| 同一個人收到兩次 | **立刻暫停**相關活動，然後找管理員查原因 |
| 登入連結打不開 | 回登入頁重新要一封，並在同一個瀏覽器打開 |

## 7. 接入新的 IG 帳號

要先成為 HL Reply 的測試人員，再由帳號本人授權。每個帳號約 7 步，步驟見出片專案的 `ops/openreply_multi_account_20261008.md`。授權時的彈窗和登入，一律由帳號持有人自己按。

## 8. 部署（只有管理員）

線上服務在 Railway 專案 `websites-seo-app`，有三個服務：`openreply-web`、`openreply-worker`、`openreply-cron`。
部署是把本機分支用 `railway up` 推上去，**先部署 web（它會先跑資料庫更新），再部署 worker**。`scripts/deploy/` 裡的腳本是上游「從 GitHub fork 部署」的流程，我們現在沒有用它。
部署前先跑 `npm test`，部署後打開 `/api/health` 確認回 `ok`。
